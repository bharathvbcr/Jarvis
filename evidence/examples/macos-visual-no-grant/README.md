# Scoped visual resolution and approval refusal

On 2026-09-09 this bounded Go probe launched its own synthetic north-tenant bank, copied both executables into a private temporary directory, attached by PID, and captured only that bank window. `report.json` records the exact executable hashes. Both child processes and their temporary directory were removed after the probe; the repository's `build/` binaries were not changed.

The host sanitized the screenshot before persistence and created the 120×30 anchor from the Search label through `computer.CreateVisualAnchor`, with the trusted Member ID/Subaccount name privacy policy. Search was bounded to the Search button. Native resolution returned a unique tagged visual target with an opaque broker identity and no private full-frame digest. An `effect:read` visual click with no approval was refused as `approval_required/not_sent`. The independent bank-state bytes were unchanged.

No approval grant was created and no visual click was delivered. This report verifies real scoped capture, exact matching, public response privacy and the no-grant refusal; it does not qualify live visual input, post-pointer-movement revalidation, external hardware monitoring, Windows, or Linux.

`sanitized.png` is the redacted native frame inspected during the probe. `probe.go.txt` retains the exact Go program used, including its original local paths. `provenance.json` hashes the report, image, probe source and native Rust source/manifests sampled immediately after the passing probe and before further native changes. Source hashes are a snapshot, not a reproducible-build attestation. The bank executable has an exact hash but no immutable source-to-build attestation in this example.

The initial center crop was uniform because Search text is left-aligned. The template validator rejected it; inspecting the sanitized frame located the label. The successful probe used that visible label without weakening matching or privacy checks.
